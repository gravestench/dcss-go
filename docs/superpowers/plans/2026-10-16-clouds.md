# Source-backed Cloud Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Make one implementation commit for the whole cloud category, as requested by the user.

**Goal:** Make all 34 concrete pinned-source clouds discoverable Lua content with faithful placement, exposure, avoidance, spread, presentation, and saved ECS state.

**Architecture:** A single `world.cloud` Akara component records each occupied cell. One Lua definition per kind supplies metadata and an effect module; focused Lua policies own placement, actor exposure, monster danger, and field aging. Go supplies the existing generic context and calls one field policy after each spent player action.

**Tech Stack:** Go, Akara, gopher-lua, embedded layered Lua mods, JSON saves, Lua `_test.lua` rules tests.

**Spec:** `docs/superpowers/specs/2026-10-16-clouds-design.md`

## Global Constraints

- Target pinned DCSS source `e60ba3568b0c26447ad36ec5c7b963eb04b2778f`, including version-34 `CLOUD_GLOOM`.
- Register all 34 concrete kinds; treat `CLOUD_NONE`, `CLOUD_RANDOM_SMOKE`, `CLOUD_RANDOM`, and `CLOUD_DEBUGGING` as sentinels/selectors.
- Keep cloud-specific policy, content, names, colors, and effects in Lua files. No inline Lua in Go and no giant kind switch.
- Keep generated Lua definitions committed. Build, launch, and restore never read the C++ tree.
- Dynamic clouds use Akara components; underlying terrain stays in dense grids.
- Handwritten Go/Lua lines are at most 120 columns, preferably 80; break up multi-field literals.
- Replace the old cloud path in one pass; bump the experimental save version. No compatibility adapter.
- Make one contiguous cloud implementation commit and merge verified work into local `main`.

## Review Focus

1. Two actors take actions during one player turn: cloud decay and spread happen once, while each eligible actor gets source-timed exposure.
2. A cloud producer targets an occupied cloud cell: source strength decides replacement, and an opaque-to-clear change refreshes sight.
3. A source actor dies before its cloud: damage credit persists without a live actor reference or a restore failure.
4. A monster starts in one harmful cloud and moves to another: movement applies the source exception, while placement remains careful.
5. A mod replaces or adds a cloud file: startup validates the effective definition and restore uses its ruleset hash and kind catalog.

## File map

- `content/clouds/*.lua`: one discoverable source-backed definition per concrete kind.
- `ids/clouds.lua`, `constants/catalog.lua`, `constants/component.lua`, `constants/rng_streams.lua`: shared identities.
- `schemas/world_cloud.lua`: saved field state and version.
- `policy/clouds/catalog.lua`: effective-definition validation and lookup.
- `policy/clouds/{placement,exposure,danger,field}.lua`: four distinct rules over that state.
- `policy/clouds/effects/*.lua`: small shared damage/status/special-effect families.
- `systems/world_cloud_exposure.lua`: actor-scoped exposure at the source timing point.
- `policy/save/clouds.lua`: restore invariants; `policy/presentation/clouds.lua`: catalog-backed view metadata.
- `internal/game/{clouds.go,commands.go,view.go,visibility.go}`: generic field call and projection.
- Existing cloud producers under `policy/{magic,scrolls,potions,mutations,abilities,traps}/`: use the new placement policy.
- `internal/script/testdata/lua/tests/cloud_*_test.lua` and integrated `internal/game/*cloud*_test.go`: production-schema tests.

**Interfaces:** `placement.at(ctx, level_id, x, y)` returns the current

level_id, x, y, duration_aut, options)` resolves selectors once, applies

returns the placed entity or nil. `options` carries `kill_category`,
`killer_type`, `spread_rate`, `exclusion_radius`, and `special_ints` when
the producer needs them. `placement.remove(ctx, entity)` destroys one cloud;
the normal view/LOS path observes its opacity change.
