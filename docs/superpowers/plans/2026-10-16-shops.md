# Source-backed Shops Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Make one implementation commit for the whole shop category, as requested by the user.

**Goal:** Make gold and all ten active pinned-source shop types playable and saveable through Lua policy, Akara state, and a DCSS-style terminal screen.

**Architecture:** The wallet, shop, and stock owner are ECS components; the terrain grid holds the visible entrance. Individual Lua definition files declare shop types, focused Lua modules price each item class and execute purchases, and Go only projects state and draws/relays the shop screen. The existing item entities transfer between shop, floor, and carrier without copies.

**Tech Stack:** Go, Akara, gopher-lua, layered embedded Lua mods, Bubble Tea, JSON saves, Lua `_test.lua` tests.

**Spec:** `docs/superpowers/specs/2026-10-16-shops-design.md`

## Global Constraints

- Target DCSS source `e60ba3568b0c26447ad36ec5c7b963eb04b2778f`.
- Register ten active types; reject legacy `SHOP_EVOKABLES` and `SHOP_FOOD` and do not save selector IDs.
- Lua owns economy rules, shop type content, prices, transactions, and screen policy. No inline Lua in Go or central kind switch.
- Commit generated content; normal build, launch, and restore never read the C++ checkout.
- Use one exclusive item location and keep terrain in grids, dynamic stock in Akara.
- Limit handwritten lines to 120 columns, preferably 80; break up multi-field literals.
- Make one implementation commit for the entire category, then merge verified work into local `main`.

## Review Focus

1. A selected item disappears or changes before confirmation: reject the entire purchase with no gold or item mutation.
2. A purchase cannot fit in inventory: charge once and place the original entity at the shop entrance.
3. An antique shop displays unknown stock: quote the appropriate unknown value, then identify equipment on purchase.
4. A mod adds a shop and a save is restored under another ruleset: validate the effective type and ruleset hash before use.
5. A gold floor stack is picked up at the maximum balance: reject overflow without deleting the floor entity.
